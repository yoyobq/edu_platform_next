# Identity Family Frontend Boundary

本文件定义前端在 `staff / student` 身份族上应保留的页面、导航、数据入口与测试边界。

它用于防止 AI 或人工改动把“给某个页面放行学生权限”误当成“学生视角已经接入完成”。

## 核心原则

`staff / student` 在前端不是两个普通权限字符串，而是两类用户心智。

前端接入新身份族时，先判断用户看到的页面是否仍然表达同一个业务动作，并确认当前身份族应调用的
后端接口契约是否与原身份族一致。如果接口字段、默认返回、错误 reason 或页面动作已经不同，就不要
只在原页面上追加身份判断。

## 适用场景

适用于：

- 一个已有 `staff` 页面要开放给 `student`。
- 一个已有 `student` 页面要开放给 `staff`。
- 首页、导航、账户菜单、注册/登录后路径或业务入口需要按身份族表达不同心智。
- 同一类业务数据对 `staff / student` 暴露了不同后端接口、字段集合、默认返回或错误处理。
- E2E mock 可能把不该调用的数据入口默默 mock 成功。

不适用于：

- 纯按钮级、字段级的小权限点。
- 页面在两个身份族下确实共享同一套标题、字段、交互、默认查询和错误处理。
- `ADMIN` 管理能力本身、`slotGroup` 增量职责、临时 action 或对象级权限判断。
- labs / sandbox 中尚未收敛成稳定业务语义的实验页面。

## 前端判断顺序

改动前按顺序判断：

1. 这个入口原本主要服务哪个身份族。
2. 新身份族看到的页面标题、菜单名和 URL 是否仍然准确。
3. 当前身份族是否有不同的后端接口、查询参数、返回字段或 failure reason。
4. 页面默认查询、默认筛选和空态文案是否仍然适合新身份族。
5. 页面是否会展示另一身份族的管理字段、内部状态、审计信息或操作入口。
6. 错误状态是否应该停留在当前表单，还是切换为整页失败态。
7. E2E 是否能发现不该发生的数据请求。

如果任一项不成立，优先保留独立身份族入口或独立数据 adapter，而不是继续在一个组件里堆分支。

## 导航与路由

- 导航 provider 可以按身份族拆分。
- 账户菜单可以按身份族拆分。
- 首页和默认工作台可以按身份族拆分。
- 纯路由壳可以复用，但页面内容必须在会话身份稳定后再选择对应数据入口。
- `STUDENT` 才进入学生专用视角；`STAFF / ADMIN` 账号不要默认按学生视角处理。
- 不要只靠 `allowedAccessGroups: ['STAFF', 'STUDENT']` 完成页面接入。

## 页面与组件

可以共享：

- 纯布局容器。
- 纯展示组件。
- 头像、主题、字号、图标、按钮组、空态、加载态等无身份族业务语义的 UI。
- 不含身份族字段、默认筛选和操作语义的通用表单片段。

谨慎共享：

- 已经写死某一身份族文案的页面。
- 带有管理字段、审计字段、内部状态标签的详情区。
- 默认查询条件、默认学期/班级/教师筛选不同的页面。
- 注册、邀请、登录后落点、账户菜单等身份心智强的流程。

不应共享：

- 让学生进入 staff 管理视角的菜单或页面。
- 让 staff 误用 student 自助视角的数据入口。
- 为了减少文件数量而把两个身份族的完整流程塞进一个大组件。

## 数据入口

前端数据入口按页面语义和后端接口契约选择，不按“底层数据是不是同一类”选择。

- 如果两个身份族的后端接口、返回字段、默认返回或错误处理不同，使用不同的 API adapter 函数。
- 页面组件复用时，应通过 props 注入明确的数据入口。
- 学生视角不应请求管理视角字段后再在前端隐藏；出现这种需求时，先确认是否应调用学生专用接口。
- 当会话还在 `hydrating / restoring`，不要先用管理视角数据入口兜底，再等学生身份稳定后切换。
- GraphQL top-level error 如果代表链接、入口或整页状态失效，adapter 要转换成页面能识别的稳定 failure reason。

## E2E Mock

学生链路中的 mock 要能暴露误调用：

- 该调用学生数据入口时，断言学生入口请求次数。
- 不应调用 staff/admin 视角入口时，断言请求次数为 `0`。
- 不应调用课表、管理详情或审计类数据时，断言请求次数为 `0`。
- 保留 mock 分支时，必须配 counter；否则误调用会被 mock 掩盖。
- 学生页面只展示可见状态时，要断言不可见状态和管理字段不存在。

staff/admin 链路同理：如果页面不应进入 student 自助视角，也要用 counter 或失败 mock 暴露。

## AI 改动检查清单

AI 修改涉及 `staff / student` 时，必须自检：

- 是否只是加了 `STUDENT` 权限，但没检查页面语义。
- 是否把 student 菜单塞进 staff/admin provider。
- 是否让 student 账户菜单复用 staff/admin 的账号切换操作。
- 是否没有确认后端接口差异，就把 student 接到 staff/admin 原数据入口。
- 是否在 student 页面查询了管理视角字段，再靠前端隐藏。
- 是否在会话未稳定时首帧调用了错误身份族的数据入口。
- 是否在 E2E 里 mock 成功了本不该调用的数据入口。
- 是否缺少“请求次数为 0”的负向断言。
- 是否把字段错误、身份错误和整页入口失效混成同一种 inline error。

## 当前示例

学生学期校历是当前已确认的边界示例：

- `staff/admin` 继续使用管理视角学期校历入口。
- 纯 `STUDENT` 使用学生校历数据入口。
- 学生调用学生校历接口，只读取当前学期和可见事件。
- 学生事件详情不展示管理状态、更新时间、版本号等字段。
- E2E 断言学生入口请求次数为 `1`，管理视角入口和课表请求次数为 `0`。

## 简短结论

前端接入 `staff / student` 时，先判断页面心智和数据入口是否一致。

一致才共享；不一致就保留身份族边界，并用 E2E 负向断言防止误调用被 mock 掩盖。
