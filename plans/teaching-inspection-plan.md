# 教学检查前端 Lab 实施计划

更新：2026-10-19。Lab 的 P0–P2 已实施并通过定向浏览器验证；入口为 `/labs/teaching-inspection`，通过 Labs 菜单进入。P3 真实授权环境联调尚未完成，真实上游验收仍由后端计划跟踪。

## 目标与事实源

面向教研组长和全部管理员，完成找到课程、安排日期、核对材料、显式提交、恢复未知结果的闭环。教务身份单独不准入。

- 后端字段及行为：[API 当前契约](../../backend_next/docs/api/teaching-inspection-current.md)、相邻后端工作区的 DTO / 运行时 schema；不把本机绝对路径写入代码或 CI。
- 能力边界：[能力决策](../../backend_next/docs/capabilities/academic-teaching-inspection.md)；真实外部验收由[后端计划](../../backend_next/plans/teaching-routine-inspection-plan.md)跟踪。
- 本计划只持有前端交互与实施任务，不复制评分常量、超时时长、阻断支持矩阵或完整 schema。后端不可用时按 [后端文档入口](../docs/backend/README.md) 路由，不把旧快照当最新契约。
- 实施前按 [docs 入口](../docs/README.md) 加载 [Labs](../docs/labs-rules.md)、[上游会话](../docs/project-convention/upstream-session-frontend-ownership.md)、[认证边界](../docs/project-convention/graphql-ingress-auth-boundary.md)、[表格](../docs/ui-design/table-rules.md)与[交互容器](../docs/ui-design/ux-guidelines.md)规则。

## 页面组织与产品范围

采用一个工作台、三个可直达的类型视图。三类共用清单、安排、状态和恢复流程，材料组件独立，避免复制三套流程。

- 入口 `/labs/teaching-inspection`；`kind=lesson-plan|progress|assignment` 区分类型，缺省为教案；非法类型规范化为默认值。
- URL 保存类型、学期、教师、关键词和页码，支持刷新、收藏、前进后退；仅保存筛选条件，不保存 token、预览正文或操作凭据。
- 切换类型保留学期与筛选、重置页码，清空勾选与材料预览。切换学期清除教师筛选、勾选与预览；未保存编辑离开前提示丢弃确认。
- 使用现有页面标题与 antd 标签、筛选、表格、抽屉。初始加载只请求本地工作区；不强制上游登录，不逐行刷新上游。
- 主表显示课程、教师、三轮安排、覆盖概况与一个主操作“查看检查”；长说明、观察时间、依据及单次操作放入侧栏。
- 侧栏按“安排与轮次 → 材料 → 提交结果”组织，显示具体课程、类型和日期，避免在多个资源之间误提交。
- workspace 的资源 `status` 与显式刷新结果内 `status` 同形：消费 `state/upstreamCount/observedAt/observationVersion/effectiveCoveredCount/rounds`。轮次 `coverageBasis` 区分 COUNT／RECORD／SAVED；不把原 schedule.rounds.completed 改释为数量覆盖。
- 覆盖以服务端 status.rounds 为准：已知保存和固定历史关联保留原轮次，其他可靠日期优先，数量只补足最早空轮次至不回退的覆盖下界。例如第3轮已保存、数量为1时只覆盖第3轮，数量为2时再推定第1轮。前端不自行按次数推算轮次；数量下降或读取失败不重新开放已建立覆盖，数量增加不能确认 UNKNOWN 操作成功。
- 未观察展示“尚未刷新”，读取未知展示“数量暂不可确认”，不得替换为零。上游数量、有效覆盖、轮次依据和操作结果分别呈现；数量推定不标为本次提交成功。
- 首版不做全学期状态筛选、汇总看板、自动刷新、批量提交、连续核对队列或 AI 自动评价。
- 桌面以表格与侧栏为主；窄屏保留课程识别、轮次及操作，辅助信息移入全宽侧栏。操作支持键盘，不依赖 hover；复用项目宽度分档和深浅主题 token。

## 日期与单条检查流程

### 日期安排

1. 当前页勾选课程，选中后出现批量日期工具栏；翻页、改变筛选或类型时清空选择，不做跨页隐式选择。
2. 每个资源以已保存日期或服务端建议日期初始化草稿；允许编辑单项，也允许将一组日期应用到显式所选集合。
3. 调用 `teachingInspectionDatePreview`，展示全部所选课程与修改前后日期；预览后任何编辑均使确认失效。
4. 原样复用已通过预览的 `changes` 调用 `saveTeachingInspectionSchedule`；`expectedSourceVersion` 来自工作区，预览响应不返回来源指纹。保留旧版本，任何编辑或刷新替换依据均须重新预览；不静默拆批，不局部宣称成功。
5. 冲突时保留草稿，刷新工作区后重新对照、预览并确认；禁止自动覆盖。网络结果不明时先重新读取安排，由用户核对后再操作，不自动重发。

### 材料核对与提交

1. 打开课程侧栏先检查本账号恢复条目，有 PREPARED 时优先提供恢复材料。显式“刷新检查状态”调用 `refreshTeachingInspectionStatus`；工作区展示上次观察并注明时间。首版不额外调用只读 status 做重复读取。
2. 使用 status.rounds 的 canPrepare、blockers、retryAfter 和 retryWarningOperationId 展示操作入口；需风险确认时先完成确认，不把该阻断当永久不可操作。选择服务端允许操作的轮次；准备前展示当前日期。日期未保存或已变更时先完成安排，不能临时提交另一个日期。
3. 点击“准备材料”，调用对应 prepare；后端在准备和保存时复核可信数量，数量变化返回失效／冲突；相同数量刷新不使快照失效。以其返回快照和版本为准，不沿用准备前版本自行拼接。
4. 教案材料展示章节及可编辑评分，按 prepare 的 `material.lesson.scoreItems` 顺序展示 `name/description/maximum` 及合计，保存仍用对应顺序的 `scores`。说明档位不转为离散值门禁，保留人工调整和小数分。进度展示计划、实际与偏差。作业按“布置作业质量、批改情况、学生作业质量、检查人意见”分组映射现有十个字段，只读核对。
5. 预填内容标注“请核对后提交”，不得描述为系统实测质量或 AI 审核通过。材料阻断时说明原因；没有选择候选接口就不提供候选确认按钮。
6. 人工核对后单条保存；提交期间禁用重复动作，保留提交对象信息。预览失效、数量变化或来源冲突时保留可参考的输入，但必须重新准备和核对。
7. 已知保存成功直接展示成功，远端 ID 为空或数量回读未增加不能降级。刷新本地列表；不额外自动发起上游回读。

截图依据：[教案评分表](../docs/frontend/cdeec415-b8dc-4b01-bdfc-211e7a8eb936.png)、[作业评分表](../docs/frontend/29AF899E792128756A00A6158BF7ACE3.png)。评分定义由后端持有，不在前端复制九项表；不照搬截图大面积彩色表格。截图中的课程、班级不进入测试数据；查看首页、电子教案、授课计划等入口尚无对应 API，首版不提供占位按钮或合成班级名称。

## 实现边界与恢复

- 放置于 `src/labs/teaching-inspection/`：公开 route 入口、access/meta、UI、流程编排、纯展示策略及 infrastructure。API、URL 编解码与恢复存储归当前 lab 的 infrastructure；不依赖其他 feature 私有实现。
- 复用学期 entity、upstream-session 公开 API 及 shared UI。GraphQL 文档按操作集中定义一次，逐字段对齐后端；不复制业务评分或归轮策略到前端。
- router loader 通过专用准入 helper 检查实验暴露及身份，注入最小账号、staffId 数据；页面不自行恢复本站登录。最终课程范围仍由后端裁决。
- 允许全部管理员或具有效教研组长身份的 staff，不能复用包含教务的通用管理准入。通过 `resolveUpstreamLoginLockedUserId` 复用身份选择策略：admin 不锁定工号，组长锁定本人；实际检查人由后端验证上游会话。
- Lab 默认 dev/prod 允许合格身份直达、`menu: true`；owner 为 frontend，`reviewAt` 为 2026-11-16。撤回移除路由、导航投影与实验注册；本轮不迁入 stable。
- `executeUpstreamSessionGraphQL` 已支持 `allowAuthRetry` 可选透传，保持其他调用默认行为。prepare/save 显式传 false；本地安排保存也关闭自动重放。
- 复用会话 entity 的登录、身份锁定和滚动 token 更新，默认不启用 keepAlive。认证分类遵守统一 GraphQL 契约，不依赖 detail errorCode 判断登录恢复。
- 准备、保存分别生成请求 ID。发送前在 sessionStorage 按本站账号存恢复条目：学期、类型、资源、动作、clientRequestId、已知 operationId；prepare 额外保留原 round、checkDate、scheduleVersion 和 retryOfOperationId。不存 token、材料正文或评分，不自动重放 save。
- 存储失败时阻止新写操作并提示，不静默失去恢复标识。刷新后优先查询 operation；账号不匹配不读取旧条目。PREPARED 只表示准备完成，必须保留恢复输入；保存结果确认、明确放弃未提交预览或取消未发送动作后清理对应条目。
- 查询到 PREPARED 后提供“恢复材料”：用户点击才使用原请求 ID、原业务输入及原检查人的当前会话调用 prepare 幂等重放，取回原预览。不用当前安排版本替换原版本；重放返回失效阻断时要求重新准备、重新核对。
- 收到明确 operation:null 的阻断响应时结束本次恢复跟踪，展示原因，修正后允许新操作；不能把认证失败或任意异常都推断为未创建操作。
- 超时、断网或认证失败不自动重发。恢复会话后按原操作 ID / 请求 ID 查询；NOT_FOUND 不证明未写入，保留原标识，刷新安排并提供继续查询入口，不因查不到就自动使用新请求 ID。
- 未知操作的重试资格、等待期限及风险确认 ID 只消费服务端返回值；显式确认重复风险后才创建新的 prepare/save 请求，并贯穿传递同一风险确认依据。
- 类型切换或筛选变化后的迟到读取不能覆盖当前视图；已发送写入仍维护原操作恢复条目，不把关闭抽屉当作取消上游提交。

- [x] D0：记录已确认页面与批量范围，登记索引，对齐后端前端预想；不将尚未实现的行为写成 current。

- [x] P0：实验准入、上游会话接入、类型深链接、工作区与日期安排；完成最小公共请求参数扩展及其回归。
- [x] P1：三类材料组件、逐项准备和提交、状态与阻断展示。
- [x] P2：刷新恢复、风险确认、迟到响应隔离、窄屏与键盘验收。请求标识落盘、禁止自动重放、操作查询恢复和账号隔离须与 P1 一起通过后，才开放真实生成／提交。
- [ ] P3：真实授权环境联调；验证后将稳定前端约定移入 project-convention，剩余任务转 followup。真实外部验收结果引用后端记录，不重复维护。

验证遵守 [测试规则](../docs/testing.md)及[分组规则](../docs/project-convention/e2e-test-groups.md)：

- 纯单测覆盖 URL/状态展示与恢复存储边界，不复制后端归轮算法做自证。
- 公共请求包装验证 `allowAuthRetry: false` 确实禁止重放，原有默认调用行为不变。
- Playwright 使用真实 router、页面、登录控制器和流程，在 GraphQL 网络边界提供合成数据；验证页面结果与禁止发生的额外请求。
- 准入：教务不能单独进入，普通 staff 不误放行，未绑定管理员可见且可进入，管理员可切换上游教职工，组长仍锁本人。
- 浏览：首屏没有上游请求，深链接及前进后退正确，切换类型不串预览，迟到结果不污染新视图。
- 安排：显式所选集合、修改后重新预览、冲突不覆盖、分页后不保留隐式选择。
- 提交：三类正常流程、单击只发送一次、认证失败不重放、成功无 ID、回读失败不撤销成功。
- 恢复：刷新后按原输入取回材料且不重复生成进度；原版本不同于当前版本也不能替换重放输入；明确 operation:null 阻断不无限查询，UNKNOWN 与覆盖分开，未知结果不自动重发，风险确认完整传递，旧快照不能提交。
- 评分：元数据顺序/上限与后端校验一致，档位说明不产生新门禁；日期保存与已预览 changes 的资源集合、版本和来源指纹一致。
- 易用性：窄屏、键盘、深浅主题；使用固定测试时钟及虚构身份，不放真实凭据或上游原始个人数据。
- 代码阶段执行类型检查、变更文件 lint、定向 Vitest/Playwright；修改路由后按规则补 core。测试注册以执行配置为准，不在文档复制注册清单。
- mock 测试仅证明前端交互与请求契约，不能证明后端持久化或真实上游保存。
